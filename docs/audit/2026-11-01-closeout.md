# Closeout Audit — 2026-11-01

> **Scope**: bote 3.4.14, every module in `src/`, closing the 3.4.x line. **Trigger**: P(-1) pass before the
> 3.5.x work. Consumers were out of scope.
>
> **Method**: four independent read-only reviews, run against the source and the built binary: the wire
> core; the network surface; tools and outbound paths; memory and CPU. Each finding was then checked at
> its `file:line`, reproduced, fixed in 3.4.15 with a test that fails without the fix, or deferred with a
> reason. A fifth pass read the current MCP specification, which is what reorders the roadmap.
>
> **Marks**: **fixed** in 3.4.15, **deferred** with a roadmap item, **upstream** to file.

**Result.** No memory-safety defect was found: a differential against a strict parser over about 313,000
lines had no diffs on the scanners, and five transports took 1,542 malformed requests each with no crash.
What it found was default configuration, resource exhaustion and places where two parts of bote disagreed.
Three of them could reach the machine from outside: any website could drive `bote bridge`'s file tools, the
other HTTP transports did not validate `Origin` at all, and an unauthenticated client could kill the
server with heap exhaustion in about 12 seconds.

## Memory

`alloc` never frees, and nothing was rewound between requests, so memory was requests times bytes.
3.4.15 adds a request arena that every transport rewinds per message. Real binaries, RSS growth:

| Scenario | 3.4.14 | B / request | 3.4.15 | B / request |
|---|---|---|---|---|
| 60 KB ping, no auth, 3,000 requests | 174 MiB | 60,817 | 0 | 0 |
| 60 KB rejected token, 2,000 | 230 MiB | 120,586 | 0 | 0 |
| 60 KB arguments to an unknown tool, 2,000 | 346 MiB | 181,404 | 0 | 0 |
| `tools/list` over http, 3,000 | 96 MiB | 33,554 | 0 | 0 |
| `tools/list` over stdio, 20,000 | 630 MiB | 33,030 | 0 | 0 |
| WebSocket header claiming 1 MiB, 300 connections | 300 MiB | 1,048,576 | 0 | 0 |

**What still grows:** a tool call that passes validation leaves `args` and whatever its handler allocates,
because the 2.0 ABI lets a handler keep both. So a client allowed to call a tool can still grow the heap, by
the size of what it sends. Roadmap 3.8.x, and 4.0 if the ABI changes.

## Performance

WebSocket: every reply waited on the peer's delayed ACK, because a frame's header and payload are separate
writes. `TCP_NODELAY` takes a round trip from **41,000 µs to 50 µs**, median.

Interleaved A/B, 15 alternating rounds, pinned to one core, 3.4.14 against 3.4.15, medians in ns:

| Bench | 3.4.14 | 3.4.15 | Delta |
|---|---|---|---|
| `codec_process_message` | 6,158 | 4,292 | −30.3% |
| `dispatch_tools_call` | 3,172 | 2,290 | −27.8% |
| `dispatch_tools_call_result` | 2,871 | 2,105 | −26.7% |
| `codec_parse_request` | 1,528 | 969 | −36.6% |
| `codec_serialize_response` | 491 | 215 | −56.2% |
| `validate_compiled_nested` | 2,372 | 2,037 | −14.1% |
| `jsonx_get_str_flat` | 150 | 187 | **+24.7%** |
| `jsonx_get_raw_nested` | 423 | 462 | **+9.2%** |
| `schema_compile_nested` | 6,167 | 6,652 | **+7.9%** |
| `auth_bearer_check_set` | 830 | 872 | **+5.1%** |

The four slower rows are real. A single-key lookup now goes through the one scanner, which decodes escaped
keys. That is the price of not having two parsers, and the full pipeline those lookups sit inside is 30%
faster. Load was about 9 throughout, so read these as ratios.

## How the fixes were proved

- **Mutation:** 33 mutants of the fixes, each killed by an assertion, a smoke check or a hang.
- **Poisoned arena:** a build that overwrites the arena on every rewind produced byte-identical output to a
  normal build over 100,000 fuzzed messages, and passes the suite. No request reads another's bytes.
- **Real binaries:** symlinks, FIFOs, hostile Origins, held ports and bearer tokens run against the built binary
  in `scripts/transport-smoke.sh`, because a unit test cannot set them up.

**Not proved:**
- agnos compiles with 0 undefined and does not run here. `_fs_open_missing`'s agnos branch and the `-1` it
  relies on are read from the syscall peer, not run.
- Only a bind failure runs for real among serve failures.
- The outbound deadline is tested against a silent server, which the read deadline stops. No test covers a server
  that drips bytes, which only the total budget stops: removing that one option alone survives.
- CI runs the pinned toolchain only, so it cannot see the signature compare in `jwt_verify_hs256` removed.

## Corrections during the pass

Two defects of this pass's own were caught by its own measurements, and are recorded because the way they were
caught matters:

- Making an empty `BOTE_BEARER_TOKENS` refuse to start broke every valid token list too: the function already
  returned 1 for "enabled". The smoke only tried the empty case. The memory run failed to start a server, which is
  how it surfaced, and the smoke now starts one with real tokens.
- The prototype arena copied `args` to the heap before validation, so the attack it was meant to stop still
  worked through an unknown tool. A test now asserts 0 bytes for that path.
